# 0.7 原子岛重设计

依据 [doc895 原子通知规范](https://dev.vivo.com.cn/documentCenter/doc/895)（2025-09-03 更新；2026-10-11 在线查阅）设计，使用 [doc896 技术规范](https://dev.vivo.com.cn/documentCenter/doc/896) 的本地 Bundle 字段。生产接口与服务端没有改动。

| 状态 | 收起态 | 展开模板 | 唯一胶囊按钮 |
| --- | --- | --- | --- |
| 目标专注 | 专注中 + 系统进度环 | 2：两个节点的进度可视化 | 暂停 |
| 自由专注 | 专注中 + 系统加载图标 | 2：显示真实计时，进度为 0，不虚构目标 | 暂停 |
| 暂停 | 暂停中 + 已暂停时间 | 1：当前五分钟提醒轮次 | 继续专注 |
| 主动休息 | 休息中 + 系统加载/进度图标 | 1：累计或剩余休息时间 | 结束休息 |
| 本段结束 | 专注结束 + 系统完成图标 | 3：有效专注 / 累计暂停 | 查看总结 |
| 今日结算 | 今日结算 + 系统完成图标 | 3：今日有效专注 / 专注次数 | 查看总结 |
| 离开提醒 | 专注提醒 + 系统加载图标 | 1：当前 15 / 30 / 60 分钟阶段 | 开始专注 |

公共动态图标只放在摄像头右侧，直接调用 rightTemplate=2/3 及 progressState=1；暂停按用户指定使用计时文本。保留规范要求的左侧品牌图标，以及进度模板必需的两个节点图片；它们不承担操作入口。辅助区 subInfo=2 为单个胶囊，不再传多图片及多操作列表。主标题固定为短状态词，移除事项名称、拼接长说明和重复按钮标签。左右统计取实际会话的 paused_seconds 与既有结算的 total_seconds / session_count。

原子通知每次成功发布后至少间隔 10 秒才刷新，期间的计时变化及状态切换合并到最新状态。仅首次执行 startForeground，此后通过同一通知 ID 执行 UPDATE；不因开始/暂停/结束模板切换重新 CREATE。前台服务首次启动仍立即履行系统要求。changedRecord 持久保存，并在覆盖安装后承接现有通知序号，避免低序号被系统丢弃。

暂停以每五分钟为一轮；很晚恢复只处理最新轮次。新一轮到达时通过 forceShowCard 请求主动展开，成功发布后持久记录本轮 token，服务重建不再次展开。原子岛可用时，提醒沿用同一原子活动，不再额外发送普通提醒或覆盖层；场景不可用时保留普通通知兜底。原生场景查询只读取本应用，未增加授权写入或扩大固件适配范围。

暂停页面恢复 v0.6 的分栏毛玻璃：显示事项已暂停、暂停时钟及点击/回车继续。新增运行状态卡片和提醒按钮栏在暂停时隐藏，首页 60% 缩放保留。断网后继续操作保留暂停，原有说明文字提示重试，仍通过同一点击入口执行。

55 项 JVM 测试、12 组本地页面回归、release 编译与 lint 通过。页面截图只验证 APK 页面；未启动模拟器或连接真机。OriginOS 原生卡片字距、公共动画、主动展开及刷新的真实表现，仍按 [验收清单](android-v0.7-validation.md) 使用 release APK 验证。
