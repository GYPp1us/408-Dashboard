# 前端授时与刷新节奏审计 · 0.7.6

审计日期：2026-10-20。代码基线：`e9385833b566a8df70f19bce5deca661d24f0d9b`。

本文件整理现状、受控复现及后续重构应遵循的时钟契约。没有修改应用运行逻辑、生产服务或 Release。这里的周期是代码请求的周期，实际执行会受网络、主线程、WebView 和系统调度影响。

## 1. 结论及早期实现

当前只有部分组件使用同一个秒调度器，没有形成覆盖网页、APK WebView、行情和原生通知的统一授时、同步跳变体系。

历史提交 `24c1158168f02e8e88c528be994edc1452b3297d`（2026-07-15，`feat: keep dashboard awake and synchronized`）引入 `secondTasks`、`runSecondTasks` 和 `startAlignedSecondClock`。后续提交 `b4f59dd` 引入服务器时钟锚点。原有秒调度没有随服务器授时改为服务器秒边界，后续时间轴、行情和原生服务又分别增加了独立时钟或定时循环。

仓库 `docs/v0.7-experience-plan.md` 明确要求原子岛、通知和应用内的状态、计时、提醒时刻一致。目录文档中未找到逐字命名为“统一授时、同步跳变”的独立规范；本审计以用户提出的这项要求、已有统一秒调度实现和该体验约定共同核对，未把下述重构建议冒称为既有文档原文。

“每秒执行一次”只描述频率。相同授时源、相同秒边界、相同视图快照、相同计时取整语义，才构成同步跳变。

| 组件 | 计算使用的时基/锚点 | 绘制触发 | 当前偏差 |
| --- | --- | --- | --- |
| 主时间、账户日期 | `app.js` 私有服务器锚点：接口 `now` 加本机 `Date.now()` 的经过时间 | 主秒循环；任务注册立即绘制 | 主循环按手机整秒排程，未按服务器整秒排程 |
| 考研倒计时 | 本机接收时刻加接口已取整的 `remaining_seconds` | 主秒循环；状态渲染时重设终点并立即绘制 | 不复用主时间的绝对截止时刻；锚点和取整单独维护 |
| 旧午休/闭馆计时及隐藏兼容节点 | 主模块服务器锚点、账户日期、配置终点 | 主秒循环；窗口重新渲染时立即绘制 | 仍执行旧窗口计算，和新时间轴并存 |

| 页面专注大计时 | 优先读原生 `runtime.timer`；回退以本机当前时间减服务端开始/暂停时间 | 主秒循环的 `focus` 和 `nativeRuntime` 都能写同一个 `#focus-timer`；原生刷新事件也会写 | 同一字段有多个写入入口；原生快照自己重新取当前时间，没有使用 JS 这一帧传入的 `now` |
| 暂停面板 | 本机 `Date.now()` 减原生或服务端暂停起点 | 主秒循环；面板进入时立即绘制 | 与校准后的页面主时间不是同一时基 |
| 主动休息及结束后休息计时 | 主动休息起点来自本机；APK 原生休息计时也使用本机时间；网页/原生的结束后总结起点口径还不完全相同 | 主秒循环；原生 Runtime 刷新 | 同时存在本机起点、实际结束时刻、打开总结时刻等不同语义，需要明确区分 |
| 今日专注、投入统计 | 服务端整秒累计值，加 `floor((本机当前时刻 - 接收/渲染时刻)/1000)` | 主秒循环；完整页面重渲染立即绘制 | 与事件绝对时间推算、原生整秒锚点的相位不同；部分基线保存在闭包中 |
| 排行榜累计、两个 diff | 最新服务端统计基线加接收后的本机经过时间；学习窗口进度又用主模块服务器时间 | 主秒循环；数据/状态变化可立即绘制 | 同一个组件混用了两类时基；最新接收时刻每次同步都会变化 |
| 首页指数的“现在”线 | 私有 `dashboardClock` 或行情快照的服务器时刻加本机经过时间 | 首页 100ms 回调及接口响应 | 不复用页面主时钟；响应接收锚点独立 |
| 指数详情的“现在”线 | 详情自己的快照/成交队列；必要时回退首页行情时钟 | 独立 100ms 回调和接口响应 | 页面与详情有独立调度；详情绘制回调缺少与主页一致的隐藏判断 |
| 完整行情页的“现在”线 | 行情快照服务器时刻，缺失时回退本机时间 | 独立 1 秒定时器，加 100ms 实时行情更新和尺寸变化回调 | 两条路径可更新同一个标记；`setInterval(1000)` 从创建时起算，不对齐统一秒边界 |
| 原子岛/原生通知 | 原生本机时钟；专注以服务端整数累计加观察锚点后的整数秒，暂停/休息以起点差值 | `Handler.postDelayed(1000)`；状态、配置、响应到达时重新评估 | 按回调后的 1000ms 排程而非统一秒边界；重锚点会影响相位；不共享网页服务器时钟 |

### 网页与 APK 并非同一份主脚本

普通网页使用 `app/static/app.js`，APK 会拦截该请求，使用 `android/app/src/main/assets/dashboard/app.js`。共享模块如时间轴和行情又从服务端加载。因此只修改网页主循环无法覆盖 APK，单独修改 APK 主循环也无法约束这些共享模块。

## 3. 联网与视觉效果的定时器

这些任务应与业务计时的“跳秒”分开，不能为了统一而把所有周期都改为一秒。

| 任务 | 当前节奏 | 合理职责 |
| --- | --- | --- |
| 首页完整数据同步 | 500ms 定时检查；在途去重 | 更新数据缓存，不因普通响应到达单独让时间字段跳变 |
| 页面心跳 | 500ms 定时检查；在途去重 | 维持会话，不是页面授时主循环 |
| 原生状态同步 | 标称 15 秒；受服务重调度、网络影响 | 对账/校时，不直接决定时钟绘制相位 |
| 首页、详情、完整行情实时读取 | 各有约 1 秒读取路径 | 获取服务端真实成交与状态，保留状态变化立即失效/刷新机制 |
| 行情逐笔播放 | 各自 100ms 检查；单笔最小间隔 100ms | 独立高频通道，共享时基和成交版本，不能据此在客户端生成交易 |
| 成交背景短闪 | 成交后 80ms 清除 | 一次视觉效果，使用经过时间，不参加业务跳秒 |
| 挑战状态、非实时行情摘要 | 15 秒检查 | 数据更新任务，非秒表 |
| 好友滚动 | 4 秒循环 | 界面展示，不影响业务时间 |
| 成绩纸带 | CSS 12 秒循环 | 界面动画，不影响业务时间 |
| Toast、按钮按压、过渡、交互防抖 | 一次性超时或动画帧 | 保持独立，仅处理动画/交互生命周期 |

## 4. 已确认的四类问题

### 4.1 同频但不同相位

主秒循环使用 `1000 - (Date.now() % 1000)`，时间轴却使用 `1000 - (校准服务器时间 % 1000) + 5`。因此，即使两者都只每秒执行一次，也不是在同一时刻更新。

原生服务使用执行完工作后再延迟 1000ms 的方式，又会受工作耗时、服务重新调度影响。

### 4.2 共用调度但未统一授时

同一轮 `runSecondTasks(now)` 传递了一个 JS 时间样本，但部分任务把它解释为手机墙上时间，部分任务再转换为服务器时间，部分任务忽略它，重新向原生请求一个即时计时结果。

手机自动校时、手动改时或网络重新校准时，这些路径可能产生不同的变化。客户端显示偏差不等于服务端结算记录被改变。

### 4.3 网络与注册事件绕过秒拍

`setSecondTask` 注册后马上调用任务。`applyDashboard`、新时间轴收到 `dashboard:updated`、原生刷新、部分行情响应，都能在非整秒时间直接绘制。首次出现可以初始化，真实状态变化也需要即时响应；问题是普通数据回包和重复重注册也走了相同路径。

### 4.4 起点、整数基线与取整语义各自维护

目前有绝对事件时间差、服务器整数累计加本机经过秒数、接收时刻加整数剩余时间等计算方法。仅统一回调频率，无法消除它们在校时、重新锚定和边界处的差异。

`floor` 用于累计时长、`ceil` 用于剩余时长各有意义，不能全部替换成一种取整；需要给同一个业务时间定义统一语义，并让各入口复用。

## 5. 受控复现

使用 Node VM 分别执行当前网页和 APK 的实际 `app.js`，控制 `Date.now()` 与定时队列。没有使用模拟器、真机或生产写入。探针脚本：`.tmp/audit_timer_cadence.cjs`；结果：`.tmp/timing-audit/controlled-results.json`。

两个脚本均复现：

1. 设备时刻为 `08:00:00.250`，校准服务器时刻为 `08:00:00.600`，即服务器比设备快 350ms。主循环下一次安排在设备 `.1000`；时间轴安排在设备 `.655`，相差 **345ms**。时间轴排程值按实际共享模块中的公式计算；这不是声称已在真机量得 345ms。
2. 在设备 `.250` 与 `.410` 分别注册两个秒任务，它们立即绘制在两个不同时间点，未等待共同秒拍。
3. 手机时钟比服务器快 5 分钟，同一个原始专注时间函数用本机默认 `now` 算出 **360 秒**，传入校准后的服务器时间则为 **60 秒**。这个函数还用于向原生传递专注累计值，不能仅视为没有影响的备用显示代码。这是构造条件下的时基一致性复现，不代表用户当前设备存在 5 分钟偏差。

当前已有时间测试主要覆盖账户时区、日期、时长及窗口边界，未覆盖这些跨模块相位、注册时机、设备改时或校时过程。

## 6. 后续重构的时钟契约

以下为审计时提出的契约；0.8.0-rc1 的首批实现及未覆盖范围见第 9 节。

1. **一个授时服务。** 服务端时刻是业务权威；请求记录发送/接收时间和样本版本，避免旧响应覆盖新样本。运行期间以单调时钟推算经过时间，网页用 `performance.now()`，原生用 `SystemClock.elapsedRealtime()`；原始设备墙上时间仅作启动/恢复等情况下的明确回退。
2. **一个业务秒拍。** 基于校准后服务器时间安排下一秒边界。每次只采样一次，生成共享 `frameId / nowEpochMs / stateRevision`；组件使用该快照计算，不能各自重新取当前时间或建立局部偏移。
3. **一个时间字段写入者。** 原生 Runtime 与网页专注模块不能分别写同一个计时 DOM。主时间、考研、日程、累计、暂停、休息、排行榜等作为同一批业务帧提交。
4. **联网只更新缓存。** 普通响应不直接让时间字段跳变，也不重置秒拍。新增记录和非计时信息可以独立更新。真实开始、暂停、继续、结束、结算等状态变化，立即以一个完整一致的快照渲染，之后回到统一秒拍。
5. **逐笔成交保留 100ms 通道。** 它和业务秒拍共享授时、生命周期和状态版本，按服务器成交序号播放；0.1 秒最多一笔、80ms 短闪不变。不能为了“统一”降低为每秒一笔，或在客户端虚构成交。
6. **隐藏时停止绘制，恢复时补最新帧。** 不逐个补画遗漏的秒数或过期成交。不改写业务起点；统一处理可见性，销毁失效订阅。
7. **原生通知共享时间语义。** 对齐相同的校准时间和秒编号，但跨进程及 ROM 的实际落屏不能保证同一毫秒。主动提示 15 秒内冻结岛的计时画面属于已接受的明确例外，内部计时继续，真实状态变化立即处理。
8. **校时和真实数据更正分开处理。** 小幅时钟校准不应造成重复秒或反复来回跳；大幅校正、服务器真实记录修正和跨日要按明确流程统一重建快照，不能用永久禁止数值回退的方式掩盖正确数据。

## 7. 验收应补充的项目

- 服务器与设备有非整数秒偏移时，所有业务时间字段仍使用同一帧。
- 500ms 网络回包、任务重复注册、切换面板，不会额外让纯计时时间字段跳变。
- 手机时间前后调整、接口延迟变化、旧响应晚到时，授时和状态版本仍一致。
- 跨分钟、午夜、午休/开盘、暂停/继续、结算边界时，数字和状态标签一致。
- 页面隐藏后不绘制；恢复只取最新状态，不回放遗漏帧；后台原生计时仍满足既定要求。
- 行情 100ms 通道保持真实成交顺序；没有新成交时不反复提交整条曲线。
- 岛主动提示冻结 15 秒的例外与普通逐秒更新、状态立即透传分别验证。

## 9. 0.8.0-rc1 首批实现（2026-10-21）

本节为审计之后的实施记录，前文保留 0.7.6 基线口径。

- 新增 `dashboard-clock.js`，网页与 APK 使用同一份模块。以接口 `now` 为业务时间锚点、`performance.now()` 推算经过时间，按服务器秒边界生成不可变帧。小幅校正渐进消化，大幅校正统一在下一完整帧体现；请求顺序保护避免旧授时覆盖新样本。
- 主时间、账户日期、考研、原有窗口兼容节点、新全天时间轴、专注、暂停、休息、今日累计及投入/排行榜计时接入共同秒拍。注册或重建组件复用已提交帧。APK 原生 Runtime 每个业务帧读取一次，网页专注计时保留单一写入入口。
- 普通首页同步响应合并到下一业务帧；开始、暂停、继续、结束、结算等真实状态变化立即提交完整帧。写操作前后的视图版本及原生状态版本用于拒绝过期响应，排队数据在提交时再次校验。
- 页面隐藏时停止业务秒拍，恢复时只绘制当前帧；本机主动休息使用单调经过时间。已有联网节奏及会话保活不变。
- APK 内置时间轴和授时模块；对现有生产 HTML，拦截的主脚本流会先加载授时模块，因此无需部署生产服务即可使用本次 APK 改动。
- 原子岛单独接入已验证固件的 `SuperXChronometer` 参数，纯走秒由 SystemUI 完成；详见系统计时探测记录和本版说明。网页与原生尚未统一为同一个校准服务，因此不能声称其实际落屏同相。

本阶段没有改成哈希/版本探测协议，500ms 完整数据请求和原生 15 秒同步仍保留；行情 100ms 逐笔通道、独立行情时钟、原生 WakeLock/Handler 生命周期、往返时延授时和更多渲染缓存优化留待后续。未修改生产业务计算或数据库，没有量化耗电改善。

验证：42 项前端定向测试、51 项原生相关测试、签名 Release 构建和 lint（0 错误）；网页与 APK 旧 HTML 模式各两种尺寸的浏览器冒烟检查通过。滑动器旧测试中的两个“同一入口再次使用”用例在 0.7.6 基线同样失败，未将本版称为全套测试通过。未启动模拟器；最终手机效果由用户安装 Release APK 验收。
