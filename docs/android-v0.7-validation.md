# 0.7 真机验证清单

由设备所有者从 GitHub 正式 Release 下载 `Mutsumi-Focus-v0.7.0.apk`，覆盖安装。此清单是待验收项目，不是已完成的真机测试记录。版本名 `0.7.0`，版本码 `14`，沿用既有签名。

## 基础与原子岛

1. 覆盖安装后账户、事项及已有场景授权保留；竖屏顶部没有独立设置条。原网页设置页内可打开“原子岛与提醒”。通知、原子岛、后台计时状态文字与按钮可读；强提醒默认关闭。
2. 自由计时启动一段：收起态左侧累计有效专注 m:ss，右侧公共加载动态图标；展开为进度可视化模板，显示真实计时和一个“暂停”胶囊。选择 25 分钟目标启动后，右侧为公共进度环，展开卡片为两个节点的目标进度。长事项不进入岛上文案，不应触发跑马灯或挤压时钟。
3. 暂停后有效专注时长冻结；收起态左侧“暂停中”，右侧显示已暂停时间。展开为强调信息模板，平时为“继续专注”胶囊，提醒到达时改为“关闭提醒”。快速重复点击不重复提交；暂停页面保留 0.6 分栏及点击/回车继续，提醒到达时只增加紧凑的关闭按钮，不显示复杂状态卡片。
4. 正常结束后，左右对称模板分别显示实际开始、结束时刻，中间线上显示累计有效专注（排除暂停）；右岛使用公共完成图标，展开只有“查看总结”胶囊。约 30 秒后结束统计收岛。今日结算同样使用左右对称模板，分别显示今日有效专注和专注次数，核对数字与真实结算报告相同，不能沿用最后一段时长。

## 提醒与休息

5. 暂停满 5 分钟时主动展开原子岛，显示第 1 轮提醒；继续保持暂停至 10 分钟时显示第 2 轮，每轮只主动展开一次。重新打开/重建服务不能再次主动展开同一轮；很晚恢复时直接显示当前轮次，不连续弹出已错过的轮次。
6. 在其他应用或锁屏上检查：原子岛可用时，同一提醒不额外发送普通提醒或应用覆盖层，提醒胶囊为“关闭提醒”；原子岛关闭/场景不可用时，普通提醒保留“继续专注”或“开始专注”，另有“关闭提醒”；可选强提醒也有关闭按钮。已有延后/收起协议继续保存在本机，但岛上不放这些入口。
7. 正常结束后的 15、30、60 分钟阶段到达时主动展开，胶囊为“关闭提醒”。核对任意一轮点击关闭后，本段所有后续离开提醒停止，重开应用不恢复；下一段结束后正常重新提醒。暂停提醒关闭后保持暂停、有效计时不变，后续五分钟轮次停止；新的暂停重新启用。已处理阶段不重发；较晚恢复只显示最新阶段。今日结算后停止全部离开提醒。
8. 主动休息选择自由计时及 15 分钟目标：与暂停同为强调模板，收起态左“休息中”、右已休息 m:ss，展开采用 h小时m分钟或m分钟s秒，只有“结束休息”胶囊。退后台、锁屏、关闭后重新打开，起点不重置；目标到达后继续累计、不自动恢复专注，休息期间不催促。
9. 连续观察岛上的文本和动画一分钟，并快速执行暂停/继续：客户端每秒统计并请求计时更新；状态确认后立即透传，不等待下一秒或十秒窗口。分别从 APP 与原子岛操作，核对实际 ROM 能否及时切换、逐秒呈现。小胶囊超过一小时显示 60:xx、125:xx，不回绕、不截断；大卡按小时/分钟/秒适配。APP 内操作与计时即时执行。核对无反复 CREATE、重复提醒、跑马灯、文字折叠或刷新闪烁。
10. 覆盖安装并重建服务，确认已有通知继续更新，没有因 changedRecord 回退而丢弃更新。已撤销场景时验证普通通知及可选强提醒兜底，不重新修改或注册其他应用的场景。

## 页面与恢复

11. 竖屏第一屏直接操作当前专注；今日投入在下方，图表与附加操作可展开；浏览长内容时底部计时/暂停/继续可用。结束后不展示“准备下一段专注”额外面板，原有快捷专注及统计仍可用。休息期间仍可浏览统计及详情。
12. 输入设置草稿、展开详情并滚动，旋转横竖屏；页面、草稿、计时与展开状态保持，键盘不遮住当前输入和主要按钮。横屏首页比例仍均衡；深浅模式与陶土、鼠尾草、海蓝配色可读。所有岛上状态图标、进度环、加载/完成图标和按钮颜色跟随当前页面主题；主题切换后不保留旧色。
13. 断网后从未到提醒的暂停岛执行继续/暂停：保持真实计时状态；网络恢复后再次点击可重试，APP 提供未确认说明，不假装成功。提醒到达时胶囊为关闭提醒，关闭只执行本机操作，断网也可立即关闭。暂停分栏上的关闭按钮用触摸和回车分别检查：关闭不能误触恢复专注。恢复网络后先回读实际状态；若此前请求已完成，不重复结束或错误恢复。退出登录清理本账号运行状态。
14. 通知被系统降级、原子岛关闭或授权不可用时，普通通知仍包含对应状态与操作。已有授权无需反复配对；重新配对、启用与撤销引导字体、步骤、结果和返回入口可用。

记录问题时提供 APK 版本、手机型号/系统版本、操作入口、操作前状态与实际结果；岛渲染问题附相应截图。原子岛卡片、原生 PendingIntent、后台保活和输入法行为目前均待真机验证。

若仍有状态切换延迟，可检查 `FocusService` 日志的 `queueMs`、`responseMs`、`appliedMs` 和 `publishMs`，区分请求排队、接口响应、主线程应用和通知提交；不需要提供 Cookie 或账户内容。慢后台请求不应挡住本机按钮操作，也不应在操作完成/失败后覆盖新状态。跨设备变化在后台按既有 15 秒回读发现，发现后立即通知；该发现周期不代表本机操作等待十五秒。

新增核对：开始/结束按账户时区显示，手机改为其他时区不改变口径；跨日标识明确。累计秒数与实际报告一致，格式变化不应使时长减少、回绕或停在目标值。源码与 release 标签应对应同一版本提交。
